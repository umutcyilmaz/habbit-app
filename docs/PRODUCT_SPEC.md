# Product Spec

## Product Summary

Bloom is a privacy-first sexual wellness, arousal awareness, and habit improvement app for adults. It helps users pause before automatic habits, reduce adult-content loops, reflect on triggers, notice sensitive windows, reduce rushing, and build calmer routines.

Bloom is built around awareness and agency. The product should never imply that the user has failed, needs to be fixed, or is being watched. Users remain in control.

## Target User

Bloom is for adults who want a more mindful relationship with arousal, adult content, and masturbation habits. They may notice automatic evening loops, rushed sessions, boredom-driven browsing, or patterns that do not feel aligned with how they want to spend their time.

The user does not need to want abstinence. Bloom supports reflection, pausing, and intentionality without making stopping the goal.

## Example User: Mert

Mert is 29.

Mert often opens adult content automatically in the evening, especially when bored, alone, or after social media. Sometimes this leads to rushed masturbation that does not feel very mindful or pleasurable.

Mert does not want to stop masturbation completely. He wants to become more aware, less rushed, and more intentional.

Mert's goals:

- Pause before automatic habits.
- Reduce adult-content loops.
- Masturbate more mindfully.
- Reduce rushing.
- Understand triggers.
- Improve arousal awareness.

Mert's starting pattern:

- Boredom appears often.
- Evenings feel sensitive.
- Adult content sometimes starts automatically.
- Adult content sometimes comes before rushed masturbation.
- Preferred support style is Balanced.
- Medical red flags are not present.

## Core Principles

- Progress is awareness, not abstinence.
- Build awareness before automatic habits.
- Reflection should be calm and non-judgmental.
- Protection should be gentle support, not a hard blocker.
- Users should always feel in control.
- Privacy and deletion basics are core product features.
- Sensitive content should be minimized, stored locally when possible, and excluded from analytics.
- Bloom should avoid diagnosis, treatment, and performance framing.

## Tone Rules

Bloom's tone should be:

- Calm
- Private
- Mature
- Non-judgmental
- Supportive
- Discreet
- Product-focused
- Clear
- Optional

Bloom should avoid:

- Shame-heavy language
- Therapy-heavy language
- Clinical diagnosis language
- Claims of cure or treatment
- Competitive scores
- Alarmist labels
- Surveillance framing

## What Bloom Avoids

Bloom is not:

- A NoFap app.
- A relapse counter.
- A porn addiction app.
- A medical diagnosis app.
- A "last longer" performance tracker.
- A shame-based blocker.
- A medical treatment product.

Bloom should not use product mechanics that punish the user, label them as failing, or frame progress as abstinence.

## MVP Modules

Must-have MVP modules:

- Onboarding quick path
- Safety note
- Privacy / trust screen
- Today dashboard
- Quick Check-In
- Pause Now
- 90-Second Pause
- Daily Log
- Basic Exercises
- Basic Progress
- Basic Protection
- Profile & Privacy
- Data deletion basics
- Notification privacy basics
- Empty states
- Error states

Should-have MVP modules:

- Content Support
- Arousal Awareness Practice
- Weekly Review
- Next Week Focus
- Sensitive Window suggestions
- Data export
- App Lock
- Reminders

Later or premium modules:

- Long-term trends
- Advanced insights
- Custom routines
- Multiple profiles
- Full coaching library
- Advanced reports
- Deep adaptive plans

## Non-Goals

The foundation phase will not include:

- Full app screen implementation.
- Backend services.
- Authentication.
- AI API calls.
- Payment integration.
- Medical diagnosis or treatment workflows.
- Blocking or surveillance systems.
- Performance scoring.
- Public social features.
- Sharing feeds.
