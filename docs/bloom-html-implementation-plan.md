# Bloom HTML implementation plan

Date: 2026-10-12. Branch: `feature/product-ui-v1`. Target navigation: **Ana sayfa | Library | Kegel | Profil**. Phase 11.3 implements these four visible tabs. **Log | Exercises | Progress | Protect** remain registered as hidden compatibility routes; the Progress tab is not restored.

Sources: actual CSS/SVG/JS and `flows`/`fig` inventory in [.local-design/kegel/tasarim.html](../.local-design/kegel/tasarim.html), event handlers in [prototip.html](../.local-design/kegel/prototip.html), native routes, feature screens, controllers, read models and storage schemas. The folder name does not constrain product scope. HTML examples, prices, testimonials, counts and toy algorithms are design fixtures, not approved product facts. Existing V4 functionality must be reused.

The static board defines **21 flows / 88 labeled screen states**. Every label is covered below. Behavior-only states are inventoried afterward. Native capabilities and approval gates are planning requirements, not implemented promises.

## Kegel persistence compatibility decision

The old v7 normalizer intentionally discards unknown fields. Adding Kegel to v7 without a version change would allow an older build to silently drop new sessions. A separate Kegel store would introduce parallel lifecycle/retry coordination. Use the established versioned envelope/coordinator instead: v8 adds only a validated Kegel slice; copy v7 slices without alteration and retain the original v7 key byte-for-byte. v7-and-earlier have no genuine Kegel sessions; migration supplies an empty slice, never preview data. Failed migration leaves the source untouched and follows the existing unconfirmed-save safeguards. Malformed Kegel data rejects hydration and is backed up rather than dropped.

Downgrading is not a supported write-merge workflow: a v7 build sees its retained pre-upgrade state, while v8 is authoritative for this build. A future cross-version merge/cloud sync/retention policy needs separate design approval. No existing user storage is opened, cleared or migrated during Simulator QA; QA uses a unique isolated namespace with the same coordinator.
