# 15-Day Product Reset

Phase 1U introduced the third executable new-product feature; Phase 1V removes the mandatory post-reset assessment. It shares this directory with legacy Ten-Day Reset, whose screens, README, and `/reset/...` routes remain unchanged. New product Reset uses only:

- `/bloom/reset/baseline?journeyId=...`
- `/bloom/reset/progress?journeyId=...&attemptId=...`
- `/bloom/reset/completion?journeyId=...&attemptId=...`

Each route delegates to `screens/ResetProductScreen.tsx`. `useResetFeature.ts` connects canonical provider reads, display time, navigation, and the existing flow API. `resetController.ts` coordinates commands and receipts; `resetView.ts` validates route presentation and uses existing Reset selectors. There are no direct persistence calls, pure transition calls, new provider accessors, or mutation IDs/timestamps generated by these modules.

Phase 1W baseline collects only the four current `CurrentResetBaselineSelfReport` fields: erection decline, stronger/faster stimulation need, longer time to climax, and difficulty arousing without intentional explicit sexual content. It uses the specified Turkish questions/options and semantic test IDs while retaining existing components/styles. All four answers start unanswered and are required; the stronger/faster question intentionally has no `notSure`. Explicit submission calls `startFromBaseline(selfReport)` with exactly these four answers, without IDs, timestamps, aggregates, or scores. The flow prepares identities and one canonical timestamp for capture/start. Only a durable receipt replaces the route with the canonical active attempt's progress route.

The pure Reset start transition builds the baseline from current accepted Tracking state through `getResetTrackingSnapshot(tracking, capturedAt)`. All completed sessions ended at/before capture contribute, including when Tracking is disabled; unfinished or future-ended sessions do not. It stores mean erection quality and explicit-content ratio for one or more observations, and chronological mean start-to-start seconds for two or more. Missing means unavailable, not zero; observed zero ratios and numeric precision are preserved. Restart, undo, completion, and persistence retry never recapture the baseline.

Legacy three-question self-reports remain historical compatibility only. Exact old/new shapes validate without a stored discriminator or fabricated answers; old active/completed journeys and historical assessments continue working. Persistence stays v7 / `bloom.localState.v7`.

Progress comes from `getResetProgress(reset, displayTime)` and `getResetRestrictionStatus(reset, displayTime)`. The exact boundary is 15 elapsed 24-hour periods after the **current attempt** start. A stale `active` status cannot extend behavioral restriction. The display combines current selector-derived completed days with the stored best for an effective best and never persists ticks. At the boundary, an explicit Continue opens completion; a second explicit action invokes `completeElapsed()`. The transition records the actual period end from the attempt start, independent of when it is observed. It produces `completed` directly without an assessment. Durable completion returns to existing Today (`/(tabs)/today`).

Manual violations support `masturbation`, `intentionalExplicitContent`, and `masturbationWithExplicitContent`. A confirmation explains the restart and is consumed before one `recordViolation({ reason, source: { kind: "manual" } })` call. The flow creates all mechanical identities/times. The transition archives the prior attempt and starts its replacement; intentional-content effects on active Content-Free are part of the same atomic Reset command. The feature never issues a separate Content-Free write.

History preserves violation IDs, attempt IDs, reasons, sources, occurrence/recording times, recorded status, and undone tombstones. Only the latest recorded Reset entry is offered as a candidate for `undoViolation({ violationId })`, regardless of manual/session source. This does not promise reversibility: the transition owns archived-attempt linkage, Content-Free linkage, source ownership, best restoration, and tombstones. A rejected undo shows neutral unavailable feedback. Successful undo restores the prior canonical attempt and linked Content-Free state atomically.

Old lifecycle: `15 days → assessment_pending → assessment → completed`. Current lifecycle: `15 days → completed`. No assessment form, command, semantic flow intent, or executable assessment route remains. Completion preserves the Tracking enabled/disabled preference. Valid persisted `assessment_pending` journeys normalize to completed through existing v7 writeback; valid historical assessments stay readable as optional metadata. The final result UI remains deferred.

All commands recheck the exact scalar route IDs and displayed immutable Reset snapshot against `getAcceptedState()` immediately before dispatch. Undo also checks the exact current candidate. Stale, missing, repeated, mismatched, completed-state, or unmounted handlers cannot target another attempt. The controller captures the exact accepted successor before awaiting persistence: after restart/undo, the old URL is not mistaken for the successor identity. Save/retry feedback remains visible until acknowledgement. Only the exact current durable successor may navigate to its new/restored progress route or Today.

Every dispatched mutation preserves `Promise<BloomPersistedMutationResult>`. Duplicate presses share an in-flight operation, and failures retain the original accepted state and retry token. `retryPersistedMutation(retryToken)` retries persistence only, without replaying commands or regenerating IDs/timestamps. Navigation is guarded while saving; receipt callbacks and explicit continuation recheck current identity. Mount, render, refocus, and display ticks never trigger a write or automatic lifecycle redirect.

`scripts/verify-bloom-reset-feature.ts` runs through `npm run verify:persistence`, alongside route and existing product verification. Persistence remains version 7 at `bloom.localState.v7`, with narrow legacy lifecycle normalization and no version bump or migration changes. Home/Today remain unwired. Phase 2B adds separate [Reset recommendation review/acceptance](../reset-recommendation/README.md), which prepares baseline-pending without starting the period; Starting recommendation remains deferred; Phase 1Z adds separate [Panic](../panic/README.md) and [Urge resume](../urge-control/README.md) features; the four earlier Masturbation/Content-Free routes remain ready with unchanged behavior.
