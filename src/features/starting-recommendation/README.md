# Starting Recommendation — Phase 2C

`/bloom/starting-recommendation` is ready and parameter-free. Home emits only `{ id: "reviewStartingRecommendation" }`, which maps to `{ flow: "startingRecommendation" }`. The screen reads the latest accepted `productOnboarding.result.recommendation`; navigation cannot override it with answers, dimensions, scores, timestamps, or a stale result snapshot. All eleven current product routes are now ready.

The pure view structurally validates the existing stored onboarding shape and returns its historical recommendation only for completed onboarding with null `planAcceptance`. It never rescores or infers new conclusions. The controller compares rendered onboarding, Tracking, Reset, and Content-Free references with fresh accepted state before calling only `flowActions.onboarding.acceptRecommendation()`. Canonical acceptance conflicts remain owned by the unchanged transition.

The existing atomic command records acceptance and enables Tracking, activates Content-Free, prepares Reset `baseline_pending`, or combines Content-Free activation and Reset preparation according to the stored plan. No plan starts a session. Reset still requires the existing four-question baseline before its 15-day period starts. The feature generates no IDs or timestamps and dispatches no direct tracker or Reset commands.

The controller retains the exact accepted successor when the ordinary review becomes unavailable. Failed persistence locks duplicate acceptance and exit, exposing token-only retry of that same snapshot without another command, ID, or `acceptedAt`. After durable save, Tracking and Content-Free plans replace to Today; Reset and combined plans replace to baseline using the actual accepted journey ID. Automatic navigation requires unchanged relevant accepted references. Superseded receipts do not auto-navigate; later cumulative durability can allow explicit Continue for the same accepted plan/destination. Unmounted/replaced callbacks and stale Continue handlers cannot navigate.

The hook owns provider access, durability, lifecycle, navigation guards, and routing. The shared-component screen renders observational copy and explicit actions. Close before acceptance writes nothing. No dismissal/snooze history, scoring/question change, schema change, migration, V4 styling, legacy onboarding/Today cutover, or tab change is introduced. Persistence remains v7 / `bloom.localState.v7`.

`scripts/verify-bloom-starting-recommendation-feature.ts` runs through `verify:persistence`. It exercises all four plans with the real runtime/flow/transition, atomic successors, conflicts/no-ops, same-snapshot retries, Home results, and controlled hook/screen execution. The existing Home priority, mapping, and route suites cover parameter-free contracts, payload exclusion, thin entries, and eleven ready / zero pending destinations.
